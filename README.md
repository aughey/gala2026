# Gala show caller

The original `2026 Gala Event Manual    - Run of Show.csv` is preserved. The clean extraction and editable copy live in `data/`:

- `baseline.json` / `baseline.csv`: clean extraction, with suggested calls and explicit review notes.
- `working.json`: authoritative editable show, including original source records.
- `working.csv`: spreadsheet export, regenerated whenever the viewer saves.

Run `python3 server.py` from this directory, then open http://localhost:8765. No installation or network connection is required.

The viewer reads `data/working.json` through the local server; its show title, cue order, times, actions, and caller wording come from that file. The interface displays the active file path. Changes to that file appear automatically within about two seconds when you are not editing, with no rebuild or server restart. The original CSV is input to extraction, rather than the live viewer file; `working.csv` is an output export.

## Working with the show

Edit cells; changes save automatically after a brief typing pause. Use the Columns menu for lighting, individual audio channels, camera/screens, or all fields. Cue numbers open all editable fields plus the exact original record. The Changes tab compares the working copy against the baseline. The Call the show tab provides the current cue, suggested caller script, trigger, next cue, and arrow/space navigation. Calling position stays in browser storage; it is not a record of executed cues.

## Calling the show

The live file uses schema version 3: a **program item** contains ordered **call events**. Each event has an `item_id` / `item` for grouping, a `kind` (`standby`, `go`, `set`, or `note`), its own `call` and `trigger`, and an optional `pair_id` linking Standby to Go. Array order is calling order. A single Standby event contains several lines such as “Standby DJ music” and “Standby House lights up”. Its linked Go event is one collective call, such as “Lights, DJ, Screens, GO!”. Advancing moves through these call points; later spotlight or screen transitions within the same program item remain separate events.

Source actions that share a technical moment are grouped into one proposed Standby event and one Go event. Grouping preserves separate moments and distinct triggers. Program grouping, exact order, and triggers need review. **Edit call & manage order** lets you insert a Standby/Go pair or a single Go after any event, move events earlier/later, remove a call, and undo the last removal from another call's editor. Use the department and action fields with **Add / update action on this screen** to include another department in this call and its paired call. Use **New call point: Standby + Go** for a later spotlight, camera change, or other transition. All participating departments and targets are visible on the call screen. Call wording remains editable. **Add program item** creates an item where you can add its call events. Editing the program item name renames the group; paired technical actions stay synchronized while independently customized call wording is preserved.

Standby calls have an editable `lead_seconds` of **30 seconds as a suggestion**, and a `target_time` linked to their Go's source/estimated time. They have no invented source clock time. Their countdown is calculated from the Go time minus the lead. When the Go has no time, the Standby remains on trigger. Changing a Go's time updates its linked Standby's target. Nothing auto-advances or executes lighting/sound.

Migration preserves the previous files byte-for-byte with `.v1` and `.v2` filenames in `data/`, including matching CSV files. Complete previous cue records, including any old combined wording, are also retained under `legacy_cues`; the previous individual call events are retained under `ungrouped_cues`. Source CSV and original source records remain intact. Re-running extraction does not overwrite an existing version-3 working file.

The viewer opens at **Call the show**. A **Visual stage check** compares the expected configuration before the selected call with its target after the call. Choose **After the next call** to preview the queued call instead, including the selected call's changes. The diagram accumulates prior GO and SET actions in show order; Standby and Note events do not change equipment state. Blank fields carry forward the last specified setting; equipment without a prior setting remains **Unspecified**. GO changes use a solid amber outline. SET targets use dashed blue borders and SET labels, including repeated instructions that already match the current setting. The setup panels show the program item, with **Expected time** (the scheduled script time, with source estimates or suggested standby times labeled) and a separate **Live estimate** beside it in the target setup. The live estimate uses your timing anchor and is shown in Central time; before timing starts it reads **Not started**. Untimed calls remain **On trigger**. The current setup has no timer, countdown, or timing controls. The diagram is compact so its spoken call and advance button remain visible on a typical desktop calling screen. The target setup includes the selected call wording, trigger, review status, editing control, and a Called — next call button. Full cue details, upcoming queue, and optional Start / Restart timing controls are in an expandable section below the setup panels. A next-call preview has a Return to current call button instead, so it cannot skip the current call. Standby targets preview the intended settings with a dotted amber border and a Standby label; the current expected setup stays unchanged until GO. Targets and changes are listed below the diagrams. Expand **Exact settings & source calls** for the original action text and last setting's call number. This is a cue sheet prediction assuming earlier calls completed, not live telemetry. Equipment placement is schematic because the source has no floor plan or fixture coordinates.

The current call and spoken wording appear below the diagram on the left; upcoming calls appear on the right. The queue can show the next call, next 4, next 8, or all remaining events. On smaller screens the diagrams and call areas stack. Use **Called — next call**, Space, or the right arrow to advance; Previous or the left arrow returns. Use Jump to to move directly to a call. Calls only skips notes without a technical call. The final call stays selected at the end.

Before starting timing, countdowns show the planned gap from the current cue. Press **Start timing here** as you begin calling that cue. Upcoming timed cues then show live estimates based on your actual progress. Entering another timed cue re-anchors timing to that call, so estimates follow a show that is running early or late. Untimed cues show **On trigger** and retain the last known timing anchor for later timed cues. Negative countdowns mean past the estimate; they never advance the show. Restart timing here resets the timing anchor at the current cue. The elapsed timer measures time on the current cue; the wall clock uses Central time. Position and timing persist in this browser through refresh, independently of script edits. Full screen is available in supported browsers.

All cues initially need review. Source time and estimated time are separate. Extraction estimates only use an adjacent explicitly timed row with a stated duration; they are never promoted into source time. Live estimates use gaps between those source/estimated times and your actual manual calls, rather than assigning durations to untimed transitions. Empty technical fields mean no instruction is specified, not that the equipment is off. No backlight or object-light settings were supplied. Dinner stays at 6:47 PM.

Sequential screen instructions are split into separate cues. Audio and lighting actions that appear together stay on the same row; their exact GO timing still needs confirmation. Auction conditions, unspecified triggers, segment-wide durations, the dinner duration mismatch, and the closing gap are called out in review notes. Caller scripts are suggestions, not approved production calls. Automatically generated scripts follow technical edits unless you have customized the script.

The viewer checks `working.json` every two seconds and reflects changes when you are not editing. For changes made outside the viewer, edit that JSON and increment its revision to protect against stale saves in other tabs. Editing `working.csv` does **not** import changes into the viewer. Original source content is retained in `source_records` for traceability. CSV exports retain multiline cells and quoted values; JSON retains the complete source and stable cue IDs.

To rebuild a new extraction after changing the original source, back up your working files, move the four `data/baseline.*` and `data/working.*` files elsewhere, and run `python3 extract.py`. Extraction never overwrites an existing baseline or working copy.

The server binds only to this computer. It is a local file-backed editor, with revision checks for multiple browser tabs, not a shared multiuser service. Back up the `data` directory before show day.

Use the **Set** call type for preparation instructions that establish equipment settings without a GO. Set calls appear in the calling queue and can be selected in the call editor.
